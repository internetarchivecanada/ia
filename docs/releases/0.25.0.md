# ia 0.25.0

Released from tag `v0.25.0`. Covers everything merged after `v0.24.0`:
PRs #111, #112, #113, #114, #119, #120, #125, #126, #127, #128, #133,
#134, #135, #136, #137, #138, #139, #140, #142 and #143 (issues #15,
#16, #22, #115, #116, #117, #118, #122, #124, #129, #130, #131, #132 and
#141). `ia-core` and `ia-cli` are both 0.25.0; the library is still
pre-1.0. The minor bump is because public `ia-core` types change:
`IaError` gains the variants `ItemUnavailable`, `SearchFailed` and
`AccountApi` (it is `#[non_exhaustive]`, so no existing `match` breaks),
`ia_core::account` is a new module, `ia_core::metadata` gains
`check_item_body` and `EXTENDED_ERR_PARAM`, and `RetryStats` gains
`record_retry` and `record_exchange` while `RetryMiddleware` gains
`with_stats`. It is also because several behaviors change. They are
listed below.

Like 0.24.0, the release assets ship with `SHA256SUMS` and a build
provenance attestation. `ia update` from 0.24.0 checks the downloaded
asset against `SHA256SUMS` before installing it.

## New

- **`ia account`** (#141, PRs #142 and #143), a port of the Python
  client's admin-only command (alias `ia ac`). It looks an account up by
  email address, screen name or `@`item name. With no action flag it
  prints the whole account as JSON; `--get-email`, `--get-screenname`,
  `--get-itemname` and `--is-locked` print one value; `--lock` and
  `--unlock` lock or unlock the account, with an optional `--comment`.
  `--lock` and `--unlock` send two requests: the lookup, then the lock
  with the item name the lookup returned. The requests carry the
  `logged-in-user` and `logged-in-sig` cookies from the `[cookies]`
  section of the config (written by `ia config login`) and no S3 keys.
  The cookies are sent only over https to `archive.org`, a subdomain of
  it, or a loopback host (http is allowed to loopback only). Any other
  host, or a host with a user name or password in it, stops the command
  before any request. Redirects are not followed, and a 5xx on a lock is
  not retried.
  Bulk input follows the other batch commands. Without `USER`, accounts
  are read one per line from `--itemlist <file>`, from `--itemlist -`
  (standard input), or from piped standard input. Blank lines, lines
  starting with `#` and repeated lines are skipped. `--jobs` sets the
  concurrency (default 2). Each result is one line that starts with its
  input line, and `--json` prints one object per account. `--dry-run`
  sends nothing, not even the lookup. A 429 pauses every worker for the
  server's Retry-After. The exit status is 1 when any account failed.
  Lines that name one account (the same item name) send one lock or
  unlock request and one comment between them; every line is still
  looked up. `--joblog` applies to `--lock` and `--unlock` only: a rerun
  with the same job log skips the lines it records as done with that
  action and runs the failed ones again, and `--no-resume` runs them all.
  Read actions ignore `--joblog`.
  Differences from the Python CLI: `-l`, `-c` and `-i` are global flags
  in ia-cli, so `--is-locked`, `--comment` and `--get-itemname` have no
  short form. Every lookup is checked to be the account asked for
  (ignoring letter case) before a lock is sent. `ia-core` gains the
  `account` module and `IaError::AccountApi`.

## Security

- **netrc: the wrong host's password could be sent to archive.org**
  (#129, PR #139). With one token per line in `~/.netrc`, the parser
  kept reading past the archive.org entry and returned the next
  machine's login and password. `ia config login --netrc` then sent
  those to archive.org. The parser now follows the netrc format of
  ftp(1): the first `machine archive.org` entry is used, a `default`
  entry is ignored, and a malformed file is an error instead of being
  read loosely. Quoted values, `macdef` blocks, comments, CRLF and a
  byte order mark are handled.

## Changed

- **Missing items are reported as not found** (#118, PR #119). Every
  `GET /metadata/{identifier}` sends `extended_err=1`: metadata reads,
  the read before a metadata write, and its `--dry-run`. The API answers
  a missing identifier with `200 {}`, which was read as an empty item:
  `ia metadata` printed null fields, `--exists` answered yes, and
  `ia download` and `ia list` found no files. That answer is now
  `NotFound`. An item that exists or existed but cannot be served is
  answered with an `errcode` beside `error`, and becomes the new
  `IaError::ItemUnavailable` (JSON error code `item_unavailable`). Code
  102 (data node offline) is retried by metadata reads, up to three
  attempts; 101 (creation pending), 104 (deleted) and other codes are
  not. `ia upload`'s collection check, which took the `200 {}` for a
  missing collection as an existing one, now fails with
  `CollectionNotFound` (`--no-collection-check` skips the check). A
  collection reported as unavailable is logged and does not stop the
  upload.
- **`ia search fts` works again** (#124, PR #125). The query was sent
  under `query` instead of `q`. The refreshed FTS service answered that
  with HTTP 200, no hits and an error message in the body, which the
  client ignored, so every search printed no results and exited 0.
  Result identifiers now come from `fields.identifier` (before: the hit
  `_id`, which is `identifier|sha1`); the hit's `_id` and `highlight`
  are kept in `fields`. `size` and `from` are sent as numbers. `--from`
  fetches one page, without scroll, because the API rejects `from` with
  scroll. `--num-found` sends `--scope`. An error the API reports in a
  200 body, or a body that is not JSON, is the new
  `IaError::SearchFailed` (JSON error code `search_failed`), printed as
  `search failed: ...` with exit status 1.
- **`ia metadata audit` checks every field** (#131, PR #138). The type
  and repeatability checks ran only on the twelve typed fields; an
  untyped field with several values, or with a value that is not a
  string, produced no finding. Expect new warnings on items whose
  untyped fields hold several values where the schema says the field is
  not repeatable, or hold a value of an unexpected type. An untyped
  `null` now counts as absent, like a typed one.
- **Files whose names differ only in case are refused** (#115, PR #140).
  On macOS and Windows the second such file overwrote the first and both
  reported success. Now the first in item order downloads and each later
  one is reported failed, naming both files, with exit status 1. Names
  are compared over the whole path, directories included, and not the
  filesystem, so Linux refuses the same files. To fetch a refused file,
  download it by name into a different `--destdir`.
- **The `HTTP: N requests` line counts every request** (#122, PR #136).
  It counted only the metadata request; `/download/` requests,
  redirects and range re-requests were missing. Three files through a
  datanode redirect now show 7 requests. 429 and 5xx answers from
  datanodes appear in the retry breakdown. A metadata read answered 503
  then 200 counts 2 requests, and its latency sample no longer includes
  the retry wait. `--json` output is unchanged.
- **The retry count means resends made** (#132, PR #134). A read that
  failed all four attempts reported 4 retries, now 3; a write that got
  one 5xx reported 1 retry, now 0. The retry summary `ia metadata` prints
  after a batch reads "N retries (...)" (before: "N requests retried
  (...)") and is also printed after a 5xx that was not retried. Resends
  after a connect failure are now counted. `RetryStats::record_server_error`
  counts the 5xx answer only. Library users who build `RetryMiddleware`
  by hand need `.with_stats()` for the counter to move.
- **A 429 on the read before a metadata write pauses the batch** (#130,
  PR #137). It was reported as a plain HTTP error and the item marked
  failed; now it is `RateLimited`, with the Retry-After (30 seconds when
  the header is absent), and `ia metadata modify` / `import` pause all
  workers and retry the item, as they already did for a 429 on the
  write.

## Fixed

- `<identifier>_files.xml` larger than its recorded size no longer fails
  with "download too large" (#116, PR #133). The mid-stream size cap now
  honours the same exemption the other size checks had.
- Zip listing member names are decoded (#117, PR #135): `a&amp;b.jp2` is
  listed and requested as `a&b.jp2`.
