# ia 0.30.0

Released from tag `v0.30.0`. Covers everything merged after `v0.29.0`:
PRs #180 (issue #179), #182 (issue #181), #183 and #191. `ia-core` and
`ia-cli` are both 0.30.0. The minor bump is because `ia upload` now chooses
multipart a different way, and `ia-core`'s `Multipart` API changes meaning.

## Changed

- **`ia upload` chooses multipart by file size, before the first attempt
  (#182).** This replaces the old behaviour, and it is the one change in
  this release that every `ia upload` user can notice.
  - **Before (0.29.0 and earlier):** every file was sent as a single PUT
    first. A single PUT that died on a file over 2 MiB continued as a
    multipart upload, and every later file over 2 MiB in the same run was
    switched to multipart too.
  - **Now:** a file larger than 100 MiB (104857600 bytes) is a multipart
    upload from its first attempt. A file of 100 MiB or less is a single
    PUT. A single PUT that dies is retried as a single PUT, and nothing
    switches to multipart on failure, for that file or any later one. When
    its retries are spent, the file fails with the single-PUT error.
  - "Larger than" is strict: a file of exactly 100 MiB is a single PUT.
  - The start-of-run listing of an item's unfinished multipart uploads is
    gone. A single PUT is sent even where IA holds an unfinished multipart
    upload of that file (for example one left by an older `ia`); the run
    does not list, resume or abort it, and says nothing about it.
    `ia upload cleanup <item>` lists such uploads, and
    `ia upload cleanup <item> <file> --abort` aborts one.
- **`ia upload --multipart[=<auto|on|off|SIZE>]` (#182).** It works on the
  bare command, with `--spreadsheet`, and with `import`.
  - `auto`, the default: multipart above 100 MiB, a single PUT otherwise.
  - `SIZE`: the same, with SIZE as the cutoff. SIZE is a whole number of
    bytes, or a whole number followed by `K`, `M` or `G` (either case) for
    powers of 1024, with no spaces: `500M` is 524288000 bytes. `0` is
    refused (use `on`), and so is anything else.
  - `on`, or `--multipart` with no value: every file is multipart, whatever
    its size.
  - `off`: every file is a single PUT, the same as `--no-multipart`.
  - `auto`, `on` and `off` are lower case only.
  - **The value must be attached with `=`.** `--multipart=500M` sets a
    cutoff. `--multipart 500M` does not: the flag then has no value (it
    means `on`) and `500M` is read as the next argument, an item identifier
    or a file. When that would silently do the wrong thing, `ia` refuses
    before sending any request and says to write `--multipart=500M` (or
    `--multipart=on 500M ...` for an item of that name). Scripts that put a
    file or item after a bare `--multipart` keep working.
  - `--multipart` in any form with `--no-multipart` is refused (exit 2).
- **`ia upload --no-multipart` (#180).** One single PUT per file, retried as
  a single PUT, and no multipart request of any kind is sent. It is the
  same as `--multipart=off`.
- **`--dry-run` shows, for each file, whether it would be sent as multipart
  or as a single PUT.** This is console output; `--json` output is
  unchanged.
- **A file over the cutoff resumes on a rerun** from the parts IA already
  holds, after each part is checked against the local file by size and md5.
  A rerun of the same command makes the same choice for each file. Before
  sending any part, a multipart file lists the item's unfinished multipart
  uploads (one request, or more if IA pages the listing), so every
  multipart file makes that listing. If the listing fails for good, the
  file fails without sending a part.
- **Memory:** a multipart upload reads each part whole (100 MiB, or less
  for the last) and sends a file's parts one at a time, so one file sent as
  multipart holds at most 100 MiB of part data. A single PUT streams the
  file. How many files are in flight at once depends on the command:
  `docs/usage.md`, "When a file is sent as multipart", gives the figure for
  `--spreadsheet` and `--dashboard` (up to `-j` items or files at once,
  default 8, so up to 800 MiB).

Examples, from `ia upload --help`:

```
# Every file a single PUT, never multipart (same as --multipart=off)
ia upload my-item ./segments/ --no-multipart

# Multipart only for files over 500 MiB
ia upload my-item ./files/ --multipart=500M

# See which files would be multipart, without uploading
ia upload my-item ./files/ --multipart=500M --dry-run

# Every file as multipart (same as --multipart=on)
ia upload my-item big.iso --multipart=on
```

## Docs

- The `--size-hint` examples in `ia upload --help` and `docs/usage.md` now
  use `--size-hint "$FINAL_SIZE_BYTES"` instead of a literal number (#183).
  The old literal, about 2 PB, made an item whose task failed because no
  place on the cluster fits it. No behaviour change; an empty value, such
  as an unset variable, was already refused.

## Dependencies

- `url` 2.5.9 (and `form_urlencoded` 1.2.3, which it requires), for
  RUSTSEC-2026-0592, a stack overflow in `Url::origin()` on nested `blob:`
  URLs (#191). `Cargo.lock` only.

## `ia-core`

- `upload::UploadOpts.multipart` changes type from `bool` to the
  `upload::Multipart` enum (introduced in #180, `#[non_exhaustive]`). Its
  variants are `Auto` (the default), `Always`, `Never` and `Above(u64)`.
  Code that assigns a bool to the field no longer compiles.
- **`Multipart::Auto` now means multipart above `MULTIPART_CUTOFF`** (100
  MiB). It used to mean a single PUT with fallback to multipart.
  `UploadOptsBuilder::multipart` takes `impl Into<Multipart>`, and
  `From<bool>` maps `true` to `Always` and `false` to `Auto`. Code that
  passes `false` therefore still compiles and now gets size-based
  multipart. A caller that used `false` to mean "never multipart" must pass
  `Multipart::Never`.
- New: `Multipart::Above(u64)` (multipart above that many bytes),
  `Multipart::is_multipart(self, file_size) -> bool`, and
  `upload::MULTIPART_CUTOFF` (100 MiB).
- Removed: `MultipartFallback`, `UploadOpts.multipart_fallback`,
  `UploadOptsBuilder::multipart_fallback` and
  `MULTIPART_FALLBACK_MIN_SIZE`.
