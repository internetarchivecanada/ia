# ia 0.26.0

Released from tag `v0.26.0`. Covers everything merged after `v0.25.0`:
PRs #146, #150, #151 and #153 (issues #144, #147 and #148). `ia-core`
and `ia-cli` are both 0.26.0; the library is still pre-1.0. The minor
bump is because `ia-core` gains public items (`collection::collection_rows`,
`CollectionRow`, `read_collection_spreadsheet`, and three
`*_num_found_with_timeout` functions in `search`) and because several
behaviors change. They are listed below.

The release assets ship with `SHA256SUMS` and a build provenance
attestation, as in 0.25.0.

## New

- **`ia collection create --spreadsheet <FILE>`** (#147, PR #153)
  creates one collection per row of a CSV, TSV, XLSX, ODS or JSONL file.
  It reads the files `ia upload --spreadsheet` reads, chosen by
  extension. A `collection` column gives a row its own parent; the
  `--collection` flag is the parent of rows without one. `--title`,
  `--description`, `--subject`, `--image` and `-m` apply to every row,
  and a field a row fills in replaces the command-line value for that
  row only. Every row is checked before the first request and all
  problems are reported in one error; nothing is sent if any row fails
  the checks. Rows run concurrently up to `-j/--jobs`; a failed row does
  not stop the others and the exit status is 1 if any failed. `--dry-run`
  sends nothing and needs no keys; `--json` prints one object per row.
  With `--joblog`, a rerun skips the collections already created and runs
  the failed ones again (`--no-resume` runs all). `ia-core` gains
  `collection::collection_rows`, `CollectionRow` and
  `read_collection_spreadsheet`.

## Changed

- **Single `ia collection create`** (PR #153):
  - `--dry-run` no longer sends a metadata request when an image is
    given; it sends nothing.
  - A create with an image always sends its request. Before, it was
    skipped when the item already held the same image.
  - `--dry-run --json` shows a key given more than once as an array of
    its values, and no longer shows a `mediatype` given with `-m`
    (the create drops it and sends `collection`).
- **`ia search --timeout` is applied** (#148, PR #150). The option was
  accepted on every search backend and never used. It now limits every
  search request and every `--num-found` request, from connect to the end
  of the response body, and each retry of a request gets the same limit.
  It can only shorten the client's own limits (30 s to connect, 60 s
  without response data). `--timeout 0` is rejected. `ia-core` gains
  `search::num_found_with_timeout`, `advanced_num_found_with_timeout` and
  `fts_num_found_with_timeout`; the existing function signatures are
  unchanged.
- **`ia-core` account lookup for keys** (#144, PR #151):
  `AccountInfo::email`, as returned by `auth::check_keys` and
  `auth::whoami`, is now the server's `username`, not the
  `logged-in-user` cookie. Both functions return an error when the
  server answers `success: true` without `value`. Error texts changed:
  a rejection reads "archive.org rejected the S3 keys (...)", and an
  unreadable answer "unexpected key check answer from ...".

## Fixed

- **`ia config check` and `ia config whoami` work** (#144, PR #151).
  Both failed for every account, in every release that had them (the
  call dates from v0.10.0), because they called the account-lookup
  endpoint `POST /services/xauthn/?op=info`, which needs the
  accounts-all-read privilege and a named account. They now send
  `GET /services/user.php?op=whoami` with the S3 keys only, as the
  Python library does.

## Documentation

Agent instructions were trimmed and unused helper scripts removed
(PR #146). No change to the binary.

## Known issues

- `ia search fts --dsl` returns no hits (#149).
- A row throttled by the server in `ia collection create --spreadsheet`
  is not retried within the run; a rerun with the same `--joblog` sends
  it again (#152).
- The shared spreadsheet reader passes JSONL values that are not strings
  through as text in `ia upload`, `ia metadata` and `ia tasks submit`
  (#154).
