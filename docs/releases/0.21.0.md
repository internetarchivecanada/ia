# ia 0.21.0

Released from tag `v0.21.0`. Covers everything merged after `v0.20.1`:
PRs #10, #23 and #26 to #49, the download/upload reliability series
(issues #11, #12, #14, #17, #18, #19, #20, #24, #25, #38), plus the fixes
from the series review (PRs #50 to #52). `ia-core` and `ia-cli` are both
0.21.0; the library is still pre-1.0.

## Breaking changes

- **`ia upload --retry-sleep` is gone** (exit 2 if passed). Retries wait on
  one schedule for the whole tool: a random wait up to a cap that doubles
  from 1 s to 60 s, or what the server's `Retry-After` header says. The
  attempt count stays the only knob: `--retries`.
- **`ia upload cleanup ITEM FILE` lists instead of aborting.** Aborting
  needs `--abort` (with FILE) or `--abort-all`; `--dry-run` shows what
  either would abort. A script that relied on the bare form to abort
  stops aborting and must add `--abort`. There is no prompt.
- **`ia upload cleanup --json` is JSONL**, one object per upload, not one
  array. Listing objects carry `key`, `upload_id`, `initiated`, `parts`,
  `bytes`; abort objects carry `action` (`aborted` or `would_abort`) and
  the same fields. An empty listing prints no lines.
- **ia-core**: `IaError`, `UploadStatus`, `DownloadOpts` and `UploadOpts`
  are `#[non_exhaustive]`. A `match` on either enum outside the crate
  needs a wildcard arm; the two options structs can no longer be built by
  a struct expression (`..Default::default()` included): start from
  `Default::default()` and assign fields, or use `UploadOptsBuilder`. The
  other API changes are listed below.

## Download

- A file is renamed into place only when its byte count equals the item
  metadata's `size` (and, with `--checksum`, its md5). A short body keeps
  the `.part` and is resumed with `Range`; a body that runs past the size,
  or a `Content-Range` total that disagrees with it, fails for good
  (`server reports N bytes for <name> but item metadata says M bytes`).
  `<identifier>_files.xml` and files with no `size` are exempt.
- A `416` on a resume is read from its `Content-Range` total: a `.part`
  exactly as long as a file whose size the metadata confirms is finished
  in place without another download; a longer `.part`, or one with no
  metadata size to confirm it, is removed and the file restarts, reported
  as `download resume failed for <name>: the server answered 416 ...`.
- `--min-speed <RATE>` (default `10K`, `0` disables): a stream averaging
  under the floor over the last 60 s, after a 30 s grace, is abandoned and
  resumed with `Range`. Each stall spends one of `--retries`; when they
  are gone the file fails with `download of <name> stalled N times: ...`
  and its `.part` is kept. A silent connection is now abandoned at 30 s
  rather than by the 60 s read timeout.
- With `--checksum`, a download whose md5 does not match is kept beside
  the file as `<name>.md5-mismatch` and downloaded again; the same wrong
  md5 twice in a row fails for good (`checksum mismatch for <name> twice
  in a row ...`), since the source, not the transfer, is wrong. The kept
  copy is removed once a later attempt verifies.
- A `.part` that is a symlink is removed before the resume offset is read
  and before any write; nothing is written through a link.
- Per-file retries wait on the standard schedule and honor `Retry-After`;
  in `--json` an `http_error` that carried the header shows `retry_after`.
- `ia download --help` renders its long help again, and `--checksum`'s
  help says that without it the md5 is never checked.

## Upload

- One retry policy for every IA-S3 request (the single PUT, and each
  multipart initiate, part, complete, abort and listing): `--retries`
  attempts after the first, the standard wait schedule, `Retry-After`
  honored, `503 SlowDown` and `429` retried, `BadDigest` retried (over
  https it means a body IA did not receive whole), refusals such as
  `AccessDenied` not. The single PUT polls IA's `check_limit` after a 503
  on the same schedule. Retries no longer stack with a transport layer.
- A body send that moves no bytes for 60 s is abandoned and re-sent at
  once, spending one of `--retries`; past the budget the file fails with
  `upload of <item>/<key> stalled N times: no bytes were sent for 60 s`.
  Before, a server that stopped reading could hang the upload for good.
- `--multipart`: a part that fails for good (refused, out of retries, or
  dead sends) no longer aborts the upload. The parts IA holds stay, the
  error names the upload ID, how many parts IA has, and both ways
  forward: rerun the same command to resume, or `ia upload cleanup <item>
  <key> --abort` to discard.
- `--multipart` resumes only when every part IA holds matches the local
  file by number, size and md5; otherwise a fresh upload starts and the
  stale one is left for cleanup, named in a warning. Several unfinished
  uploads of one name: the newest that matches is resumed.
- `--multipart` gets the skip check a single PUT has: a file the item
  already lists with the same md5 is skipped; `--clobber` uploads it
  anyway. The one read that gives the per-part md5s gives the whole-file
  md5, reported as the result's `md5`.
- Every multipart part PUT carries `Content-MD5`, so a part whose bytes
  arrive changed is refused on receipt; `--no-verify` skips the header on
  parts as on a single PUT. Each part's md5 also goes to IA in the
  completion request, which IA checks before accepting. An accepted
  completion is the upload: nothing is polled afterwards, and
  `--delete-after-upload` deletes the local file then. (The post-completion
  poll and the `uploaded_unverified` status existed only between two
  commits of this series and are not in any release.)
- `--no-resume` is honored by every command that resumes from a joblog
  (`metadata export`, `metadata modify`, `tasks submit` read it now).
- The rate-limit wait during the single PUT's `check_limit` poll is
  reported for the file, so the per-file progress row shows it; a spent
  transport budget says how many attempts were made; `cleanup ITEM FILE`
  with several uploads of FILE says "these uploads".

## Search and every command

- `ia search`: a `429` on any page is retried three times, waiting what
  `Retry-After` says or the standard schedule; past that the command fails
  with `rate limited (retry after Ns)` (`--json` code `rate_limited`).
- Transport-level 5xx retries, the LLM client and the self-updater honor
  `Retry-After` (the updater's cap is 30 s).
- Every command's `--help` renders its long help; `--joblog` and
  `--no-resume` help says what each command resumes; `--jobs` help says
  the default is 8 and only `ia metadata` adapts to the server.

## `--json` wire

- New keys: `retry_after` on `http_error`; `kept` on checksum errors.
- New codes: `source_checksum_mismatch`, `download_stalled`,
  `upload_stalled`, `resume_failed` (item-level errors through
  `IaError::to_json_error`). Per-file download failures keep the code
  `download_failed` with the error text as the message.
- `ia upload cleanup --json`: JSONL as described under Breaking changes.
