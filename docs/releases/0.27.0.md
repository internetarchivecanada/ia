# ia 0.27.0

Released from tag `v0.27.0`. Covers everything merged after `v0.26.0`:
PRs #157, #158, #164, #165, #166, #169 and #170 (issues #155, #159,
#161, #162 and #163). `ia-core` and `ia-cli` are both 0.27.0; the
library is still pre-1.0. The minor bump is because the release adds a
prebuilt binary and changes behavior that scripts and library callers
can see: `ia-core::tasks::wait_for_task` can now return a failed task,
`ia-core::joblog::JoblogEntry` gains two public fields, `ia account
--joblog` lines carry two new keys, and some `ia search` option
combinations that were silently dropped are now refused. They are listed
below.

The release assets ship with `SHA256SUMS` and a build provenance
attestation, as in 0.26.0. There are now four binaries, listed in
`SHA256SUMS` and covered by the attestation.

## New

- **A prebuilt binary for Intel Macs, `ia-x86_64-apple-darwin`**
  (PR #169). It needs macOS 10.14 or later and is cross-compiled from an
  Apple Silicon runner. The Apple Silicon binary, `ia-aarch64-apple-darwin`,
  is unchanged and needs macOS 11 or later. `ia update` asks for the asset
  named after its own build target, so an Intel binary updates to the Intel
  asset. The Intel binary was built and inspected on an Apple Silicon Mac
  but not run there. The macOS binaries are not notarized; a file fetched
  with `curl` runs, and a file downloaded with a web browser is refused by
  Gatekeeper on first run.

  Install on macOS (both architectures; `uname -m` picks the asset, and the
  install runs only if the checksum matches):

  ```sh
  case "$(uname -m)" in
    arm64)  asset=ia-aarch64-apple-darwin ;;
    x86_64) asset=ia-x86_64-apple-darwin ;;
    *)      echo "no macOS binary for $(uname -m)"; asset= ;;
  esac
  [ -n "$asset" ] &&
  curl -L -o "$asset" "https://github.com/internetarchivecanada/ia/releases/latest/download/$asset" &&
  curl -L -o SHA256SUMS https://github.com/internetarchivecanada/ia/releases/latest/download/SHA256SUMS &&
  grep " $asset\$" SHA256SUMS | shasum -a 256 -c &&
  chmod +x "$asset" &&
  sudo mkdir -p /usr/local/bin &&
  sudo mv "$asset" /usr/local/bin/ia-cli
  ```

- **`ia account --lock/--unlock --joblog` records the account**
  (#163, PR #170). Each line for a lock or unlock request that was sent
  now also has `itemname`, the item name the request was sent with, and
  `comment`, the `--comment` it carried (absent when no comment was
  given). Both are written on `ok` and `error` lines alike, and lines
  that name one account show the same `itemname`. A line whose lookup
  failed, or returned no usable item name, has neither key. Job log
  readers that reject unknown keys will need updating; resume reads only
  `op`, `item` and `status`, so a job log from 0.25.0 or 0.26.0 resumes
  as before, and so does one with the new keys. Other commands' job log
  lines are unchanged. `ia-core` gains `account::is_usable_itemname` and
  the optional `JoblogEntry` fields `itemname` and `comment`.

## Changed

- **`ia search` options before a subcommand name are used** (#155,
  PR #157). `-s`, `-f`, `--itemlist`, `-n`, `--json`, `-p` and `--timeout`
  given before `scrape`, `advanced` or `fts` (`ia search --timeout 5
  scrape QUERY`) were parsed and then dropped. They now apply as if given
  after the subcommand name. A flag given on both sides counts once and
  repeatable options add up in command-line order. What cannot be used is
  now refused before any request, with an error naming each item, and
  exits 1: a query before the subcommand name, `-s` or `-f` before `fts`,
  and `--timeout` on both sides of the name. A script that passed one of
  these and relied on it being ignored now fails. To search for a word
  that is a subcommand name, put `--` before it: `ia search --itemlist --
  scrape`. A subcommand's own options still go after its name.
- **`ia tasks submit --wait` ends with an error for a failed task**
  (#159, PR #165). A task in the error state ends the wait with `Error:
  task <id> failed (error state); see ia tasks log <id>` and exit code 1.
  The exit code was already 1; the message is now an ordinary error, so it
  is also printed under `-q`. With `--json` the failed catalog entry is
  still printed on stdout first.
- **`ia-core` `tasks::wait_for_task` can return a failed task** (#159,
  PR #165). It returns `Ok(Some(entry))` when the task's catalog entry is
  in the error state (color `red`); `Ok(None)` still means the task left
  the catalog. The signature is unchanged, but before this release it
  only returned `Ok(None)` for a finished wait and polled a failed task
  until its timeout, so **a library caller that treats any `Ok` as success
  must now check the value**. No `IaError` variant was added. `ia-core`
  also gains `tasks::wait_for_task_with_progress`, which calls a callback
  with each still-active entry.
- **`ia-core` `JoblogEntry` has two new public fields**, `itemname` and
  `comment` (PR #170). Code that builds a `JoblogEntry` with a struct
  literal no longer compiles until it sets them (`None`), or builds one
  through `JoblogEntry::new`.
- **Removing a subject stored as one semicolon-delimited string**
  (#161, PR #164). A remove on `subject` now deletes the field when the
  value equals the whole string, removes exactly the matching part, drops
  empty parts, and leaves no leading or trailing space or stray separator
  in what remains. The value and the stored parts are compared after
  trimming, so a subject with stray outer spaces now matches. An empty
  value or no match leaves the string unchanged. Before, a value equal to
  the whole string left it in place. List-valued `subject` and the
  `collection` rules are unchanged.
- **A control character in `user_agent_suffix` is a config error**
  (#162, PR #166). `general.user_agent_suffix` (config file or
  `--user-agent-suffix`) containing a control character made the client
  panic when it was built. It now returns `IaError::Config` (`invalid
  user_agent_suffix "...": it contains a control character`) from
  `IaClient::from_config`, `from_config_with_verbosity` and
  `from_config_no_retry`, and the CLI reports it as an error. Non-ASCII
  text and tab are still accepted.

## Dependencies

`crc32fast` 1.5.4 to 1.5.5 and `rpassword` 7.5.4 to 7.5.5 (PR #158).
`rpassword` 7.5.5 restores the terminal settings when a password prompt is
interrupted with Ctrl-C.

## Known issues

- `ia search fts --dsl` returns no hits (#149).
- A row throttled by the server in `ia collection create --spreadsheet`
  is not retried within the run; a rerun with the same `--joblog` sends
  it again (#152).
- The shared spreadsheet reader passes JSONL values that are not strings
  through as text in `ia upload`, `ia metadata` and `ia tasks submit`
  (#154).
- `ia update --check`, `ia upload` (including the deprecated `import`),
  `ia tasks` and `ia metadata` still drop options given before a
  subcommand name, the defect `ia search` had before PR #157. No issue
  tracks it yet.
