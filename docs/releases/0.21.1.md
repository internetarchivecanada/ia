# ia 0.21.1

Released from tag `v0.21.1`. Covers everything merged after `v0.21.0`:
PRs #54 to #58 and #66 (issues #40 and #65). `ia-core` and `ia-cli` are
both 0.21.1; the library is still pre-1.0.

## Fixed

- **`ia metadata modify` with a repeated field kept only the last value**
  (#65, PR #66). `ia metadata ITEM -m collection:a -m collection:b` wrote
  `collection: "b"`; it now writes `["a", "b"]`, as the Python client does.
  A batch `modify --search` with two `-m collection:` flags would have
  moved every item to the second collection alone.
- **`field[N]:value` under `modify` created a literal field** named
  `field[N]`. It now overwrites position N of the field's current list
  and keeps the other positions; a position past the end appends;
  `REMOVE_TAG` at a position deletes that element.
- **An upload whose answer never comes is a stall** (#40, PR #57). Once a
  request body has been sent in full, IA's answer must arrive within
  120 s; otherwise the request is dropped and sent again, spending one of
  `--retries`, exactly as a send that moves no bytes does.

## Changed

- Emptying `collection` through `modify` (`-m collection:REMOVE_TAG`, or
  an indexed `REMOVE_TAG` that empties the list) is refused with the same
  error `remove` already gives: "cannot remove last collection". An item
  that never had the field is not affected.
- `ia-core`: `parse_indexed_key` requires the key to end with `]`, so
  `subject[1]zzz` is no longer read as `subject[1]`.
- `ia-core`: under `MetadataOp::Set`, a key named more than once in one
  change list merges into a list; a key named once is written exactly as
  given, including a caller's array.
- `ia-core`: `IaError::UploadStalled` gains `response_secs` and
  `unanswered`; the stall message says which rule fired.

## Dependencies

- quinn-proto 0.11.15 to 0.11.19 and rustls 0.23.45 to 0.23.46, closing
  RUSTSEC-2026-0338 through 0342 and RUSTSEC-2026-0346 through 0349.
  Lockfile only; `cargo audit` reports no vulnerabilities.

## Release pipeline

- Release builds restore the dependency caches that every push to main
  keeps warm, and the release waits for the checks and the tests on all
  three platforms (PRs #54 to #58).
