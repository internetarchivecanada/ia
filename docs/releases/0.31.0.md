# ia 0.31.0

Released from tag `v0.31.0`. Covers everything merged after `v0.30.0`:
PRs #185, #167 (issue #152), #193, #195 (issues #186, #187 and #190) and
#194 (issues #188 and #189). `ia-core` and `ia-cli` are both 0.31.0. The
minor bump is because `ia metadata export` and `ia metadata audit` now
exit 1 when an item could not be fetched, and `ia tasks submit` now records
and resumes by task.
`ia-core` has no public API change (see the last section).

## Changed: what a script can notice

- **`ia metadata export` and `ia metadata audit` exit 1 when any item could
  not be fetched (#194, issue #189).** Before, both exited 0. They still
  write or report every item they could fetch first, and then exit 1.
  - `export`, in every mode (JSONL to stdout, `--json`, and `-o` to a file):
    the last line on stderr is
    `Error: <n> of <total> item(s) failed: <id>, <id>, ...`. It names the
    first 10 identifiers, then `and <k> more`, followed by `(see the joblog)`
    when there is a `--joblog`. `<total>` counts the items fetched in this
    run, not those skipped on resume. Each failed item is also printed on
    stderr as it fails (up to a limit, and not with `-q`). Nothing is written
    to stdout for a failed item; stdout holds the items that were fetched.
  - `audit` without `--json`, and `audit -o <file>`: the findings are
    reported as before, and then
    `Error: <n> of <total> item(s) could not be fetched: <id>, <id>, ...`
    is printed (first 10 named, then `and <k> more`) and the exit is 1. In a
    `-o` file the failed item has a row with severity `error` and the message.
  - `audit --json` with output to stdout: the exit is 1 and no `Error:` line
    is printed (as with `ia metadata modify --json`). Each failed item's line
    is now `{"identifier": "...", "error": {"code": "...", "message": "..."}}`;
    before, `error` was a bare string. This is the same `error` object that
    `ia collection create --json` uses.
  - Audit findings (type mismatches, missing fields and so on) alone still do
    not change the exit status.
- **`ia tasks submit` records each task in the joblog as it finishes
  (#195, issue #186).** This holds in every mode: one identifier,
  `--itemlist`, `--search` and `--spreadsheet`. A run that is killed keeps a
  record of every task IA accepted before it stopped. Before, a batch wrote
  its entries only after every result was in, and a single-item run wrote
  none.
- **A rerun skips a task, not an item (#195, issue #187).** Before, resume
  skipped every row whose item had any `ok` entry, so a failed `make_dark`
  row was never retried when a `derive` row for the same item had
  succeeded, and a log from a `--cmd derive` run made a later
  `--cmd make_dark` run skip those items.
  - A task is identified by the item and the `file` field of its entry, which
    is the command as sent (`.php` added when missing) followed, when the
    task has arguments, by a space and the arguments as a JSON object with
    sorted keys: `derive.php`, or `derive.php {"remove_derived":"*.jpg"}`.
  - The comment, priority, `--reduced-priority` and `-p` values are not part
    of it. A reworded comment does not submit the task again. A `comment`
    task argument (`--args comment=x` or an `args.comment` column) is left
    out too, because `--comment` is sent in the same field.
  - Each `ok` entry covers one row. Of two identical spreadsheet rows where
    one failed, the rerun skips one and submits the other, so a failed row is
    retried. The joblog cannot tell identical rows apart, so the earliest rows
    in the spreadsheet are the ones skipped. When identical rows differ in
    comment, priority or `-p`, the row sent again may carry the values of
    the row that was accepted.
  - The message is now `resuming: skipping <n> already-submitted task(s)
    from joblog`. It said `item(s)` before.
  - A joblog written by 0.30.0 or earlier: its `ok` entries have an empty
    `file`. Each one still skips every task for its item, as before, so an
    old log never causes a task to be submitted twice. To send another
    command to those items, use `--no-resume` or a new joblog.
  - When the joblog records every task, the command prints the resuming line
    and exits 0. With `--wait` it exits 1 instead (`--wait has nothing to
    poll ...`), because there is no task of this run to wait for.
  - `ia status --joblog` counts and lists each task separately, by its
    latest entry. Identical rows are one task there and show whichever
    result was recorded last, so a status of `ok` can hide that a rerun
    would still retry the other row.
- **`ia tasks submit --wait` with `--spreadsheet` now waits (#195, issue
  #190).** Before, `--wait` was ignored with a spreadsheet: the command
  submitted and exited 0 without polling.
  - It follows the rule for one identifier. When one task is left to submit
    (a spreadsheet with one row, or one row left after resume), `ia` polls it
    and exits 1 if the task fails, as with one identifier.
  - When more than one task is left, `--wait` is refused before any request,
    in every mode: `--wait is not supported in batch mode (got <n> tasks)`.
    It said `identifiers` before.
  - A joblog entry is not changed by `--wait`: a task that IA accepted and
    that then failed while waited on is recorded `ok`.
  - `-p` values now reach spreadsheet requests (they were dropped), and a
    malformed `--args` value is an error in spreadsheet mode as it is in the
    others.
- **`ia tasks submit --dry-run --json` output changes shape (#195).** A task
  with no arguments prints `"args": {}` in every mode; the spreadsheet mode
  printed `"args": null`. Spreadsheet lines also gain a `"reduced_priority"`
  key. The text dry run for a spreadsheet now lists the arguments.
- **`ia collection create` retries a throttled or failed create (#167,
  issue #152).** Without `--image`, the zero-byte create request was sent
  once, so a `503 SlowDown`, a `429`, a connection reset or a timeout failed
  the row at once. It now goes through the retry rules every other IA-S3
  control request uses, and the same budget the `--image` path gets: 10
  retries, waiting 1 to 60 seconds between them with jitter.
  - Retried: when the answer has no S3 error body, a `429` or any `5xx`;
    when it has one, the codes `SlowDown`, `InternalError`,
    `ServiceUnavailable`, `OperationAborted`, `RequestTimeout`,
    `RequestLimitExceeded`, `ThrottlingException` and `BadDigest`. Also
    connection failures, timeouts and resets, and a request that gets no
    answer in time. `Retry-After` is honoured.
  - Not retried: `AccessDenied` and other permanent codes, and IA's plain-text
    spam rejection (a `503` that is not an S3 error), which fails the row.
  - A row that still fails after the budget is reported as before and, with
    `--joblog`, recorded as an error. The message now begins
    `create collection failed:` and, after more than one attempt, ends with
    `(after <n> attempts)`. A bulk `--spreadsheet` run goes on to the other
    rows, and exits 1 at the end if any row failed.
  - Retries after a throttle (`429`, `5xx`) print nothing at normal
    verbosity; they are logged at `-vv`. A retry after a connection failure
    or a stalled request prints a warning on stderr.
  - Under steady throttling a row can now spend several minutes backing off
    before it fails. The `--image` path already did.

## Changed: `ia metadata export` into a file with `--joblog` (#194, issue #188)

Before, a CSV, TSV or XLSX export marked an item done in the joblog as soon
as it was fetched, but wrote the file only at the end. After an
interruption the joblog marked items done that had no row in any file, and
the rerun skipped them. Now the joblog marks an item done only once its row
is in the file.

- **Order.** New rows are held, the whole file is written to a hidden
  sibling, `.<name>.partial.<ext>`, and renamed over the output, and only then
  are the joblog entries for those rows appended. The file on disk is always
  complete. A fetched row replaces any row the file already has for that
  identifier, so a rerun after a kill between the rename and the joblog
  entries does not double a row. A kill during a write can leave the hidden
  sibling behind; the next run removes it.
- **When the file is rewritten**, with `--joblog` and without `--no-resume`:
  at the end; on Ctrl+C, after which the export exits 130 (even when that
  write fails: the error is printed and the rows stay unmarked; a second
  Ctrl+C exits at once and leaves the last complete file); and while rows
  are waiting, every 5 seconds or ten times as long as the last write took,
  whichever is longer. A hard kill loses only the rows fetched since the last
  write, and the rerun fetches those again. A write that fails during the
  run is a warning and is tried again at the next one; a failed final write
  is an error.
- **Without `--joblog`**, the file is written once, at the end, as before,
  and an interrupted run leaves an earlier file as it was. So it is with
  `--no-resume`: before, a rewrite in the middle of such a run replaced a
  complete earlier file while the joblog kept its `ok` entries.
- **Read-back.** When the joblog marks any item done (whether or not it is in
  this run's list), the rows already in the file are read back and the file
  is rewritten with them and the new items.
- **The latest joblog entry decides.** An item counts as done when its
  latest `export` entry is `ok`. An item a `--no-resume` run fails is fetched
  again by the next run.
- **`--no-resume` when it completes** rewrites the file with the rows of its
  own list only. An item an earlier run marked done in the same joblog that
  is not in this list has no row afterwards, and a later resumed run skips
  it. Give such a run a new joblog or the full list. This is as before.
- Nothing is rewritten when no row was fetched (Ctrl+C before the first row,
  or every item failed), so an existing file is left as it is.
- Ctrl+C exits 130 for this export, as `ia download` does.

Limits, all in `docs/usage.md`:

- The file keeps its permission bits. The hidden sibling is created with
  those bits plus owner read and write, so the rows are never readable more
  widely than the file they replace.
- An existing output file the current user cannot write is refused before any
  request, with `cannot write export file: <path>`.
- When `-o` is a symlink, the file it points to is replaced and the link
  stays; the format still comes from the `-o` name.
- When `-o` is not a regular file (a FIFO, `/dev/fd/N`) or is in a directory
  where no new file can be created, the file is written in place, once, at
  the end, and only a regular file is read back. An in-place write is not
  atomic: a kill or a full disk during it can leave a truncated file with rows
  the joblog marks done. The guarantee holds for a file replaced by rename.
- A hard-linked output loses its link: the output path gets a new file and
  the other links keep the old one.
- A JSONL file or stdout gets each line before its joblog entry. A kill
  between the two makes the rerun append that item's line a second time: a
  line can be doubled but is never lost.

## Changed: download

- A finished download's modification time is set with the standard library
  (`File::set_modified`) instead of the `filetime` crate (#193), because
  `filetime` 0.2.30 marks its call as deprecated on Rust 1.99 and later. No
  behaviour change is intended: the time still comes from `Last-Modified`
  when the response has it, and from the item's metadata otherwise. The one
  difference, from the pull request: if the finished file cannot be opened
  for writing, its time stays as the rename left it, with no error. This does
  not arise for the file `ia download` has just renamed into place. Not
  checked on Windows (reviewed by reading, not run).

## Examples

From `ia metadata export --help` and `ia tasks submit --help`:

```
# Resumable export to a file; rerun the same command after an interruption
ia metadata export --itemlist ids.txt -o data.csv --joblog export.jsonl

# Export to XLSX for editing
ia metadata export --search "collection:nasa" -o data.xlsx

# Fail a script when an item could not be fetched
ia metadata audit --itemlist ids.txt --json > audit.jsonl || echo "some items failed"

# Record submissions; a rerun skips the tasks already accepted
ia tasks submit --cmd derive --itemlist items.txt --joblog derive.jsonl

# Submit one task and wait for it
ia tasks submit my-item --cmd derive --wait

# Many collections from a CSV; a rerun skips those already created
ia collection create --spreadsheet collections.csv --joblog create.jsonl
```

## `ia-core`

No public item is added, removed or changed. Differences a library user may
notice:

- `collection::create_collection` without an image now retries under the
  IA-S3 policy. Its error documentation now lists `IaError::UploadFailed`
  (refused, or still failing once the retries are spent, with `(after <n>
  attempts)` in the message), and `IaError::SpamDetected` and
  `IaError::UploadStalled` from the same policy. The signature is unchanged.
- `filetime` moved from `[dependencies]` to `[dev-dependencies]` in
  `ia-core/Cargo.toml`; it was never part of the public API.
- `upload::retry` became `pub(crate)`; it was a private module before.
