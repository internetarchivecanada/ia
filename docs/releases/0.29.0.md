# ia 0.29.0

Released from tag `v0.29.0`. Covers everything merged after `v0.28.0`:
PR #121 (issue #16). `ia-core` and `ia-cli` are both 0.29.0. The minor bump
is because the release changes how `ia download` connects, which users and
datanodes can see, and adds public API to `ia-core`. They are listed below.

## Changed

- **`ia download` opens at most 6 connections to any one datanode**, from
  one machine, across all `ia` processes (#121). Whole files, byte ranges,
  and zip listings and members (`--zip-list`, `--zip-member`) all count.
  The 6 is per datanode, not a total. An item's two datanodes (`d1` and
  `d2` in its metadata) count as one server. The rules are in
  `docs/usage.md`, "Connections".
  - **The one change users may notice:** a single item with 8 or more files
    used to download 8 files at once (`-j 8`). It now runs 6 at a time to
    that datanode. `-j` keeps its name and default; for `ia download` it is
    the number of files downloaded at once across all servers.
  - Processes share the 6 through lock files in `connections/<server>/`
    under the cache directory (`$IA_CACHE_DIR`, else `ia` under the per-user
    cache directory). If the files cannot be used, `ia` prints one warning
    and the cap holds within the process. Do not keep the cache directory
    on NFS.
  - Other programs, other users, and older versions of `ia` are not counted.
- **A file of 256 MiB or more is split into byte ranges, only when the run
  downloads that one file.** It is cut into 64 MiB parts fetched over up to
  6 parallel `Range` requests. A run of more than one file, in one item or
  across items, fetches every file whole. Runs with `--search` or
  `--dashboard`, and a rerun of a batch that `--joblog` leaves with one
  item, never split. There is no flag for it.
  - An interrupted split download leaves `<name>.part.json` beside
    `<name>.part`, and the rerun fetches only the missing bytes.
  - If the server does not answer the first range request with a matching
    `206`, the file is fetched on one stream.
  - The md5 of a split file is computed in one pass once every part is on
    disk (unless `--no-verify`).
- **A datanode that answers 429 or any 5xx gets half as many connections**
  (6 → 3 → 2 → 1), after the `Retry-After` is honoured. Byte-range streams
  stop first; whole files stop 3 seconds later if the budget is still over,
  and resume from the bytes on disk. The budget grows back by one for every
  minute without a 429 or 5xx from that node, never above 6. Each drop
  prints one line, `server ia800807 asked us to slow down; using 3
  connections`; with `--json` it is a `slow_down` event. The lower budget
  lives in the process that got the answer; other `ia` processes keep
  theirs.
- **Connections are reused.** Each of a server's 6 slots owns one HTTP/1.1
  connection, which its next file or next part goes over. An idle
  connection is closed after 2 seconds, and at once on a 429 or 5xx. The 6
  counts open sockets, idle ones included. A server given as an IP address
  (with `-H`) gets no reuse.
- **Downloads use HTTP/1.1, one connection per transfer.** Before, whole
  files from one datanode ran as HTTP/2 streams on a single connection, so
  a datanode now sees up to 6 connections from one machine where it saw 1.
  IA operations agreed to this on 2026-11-18.

## Measured

From the PR #121 description, against the released v0.27.0 binary, same
client, medians of three interleaved rounds, default `-j`.

2026-11-18 (build `bb038f0`), this release / v0.27.0:

- One 2.04 GiB file: 19.32 / 6.60 MB/s (2.9×).
- Item with many small files (48 files, 210 MB): 21.72 / 21.72 MB/s (1.0×).
- Item of 1,267 tiny files: 14.1 / 14.8 s (1.04×); 13 connections opened
  against 17.
- 497 JPEGs of about 190 KB: 15.3 / 15.8 s (1.04×).

2026-11-19 (build `c1e5b59`, on a much slower link, so compare within the
run):

- One 2.04 GiB file: 8.92 / 2.58 MB/s (3.5×).
- Item with a few large files (16 files, 1.87 GB, fetched whole): 5.55 /
  5.25 MB/s.
- Two processes at once, one file each: 4.33 / 3.80 MB/s.

No sample saw more than 6 connections to a datanode pair, and every
finished file matched its md5.

## Not verified

- **Back-off after a real 429 or 5xx.** Covered by the offline tests only;
  no datanode answered either during the measurements.
- Windows: the slot files' paths and locks were neither built nor run.
- Other datanodes, locations and times of day than the measurement's.
- The request to archive.org that redirects a download takes one of
  archive.org's own 6 while it runs; nothing was measured against that
  service.

## `ia-core`

- `download::DownloadOpts` gains three fields (the struct is
  `#[non_exhaustive]`): `one_file_run: bool` (default `false`; a large file
  splits only when it is set), `connections_per_file: Option<usize>`
  (`None` is the automatic split, `Some(1)` never splits), and
  `server_slots: ServerSlots`.
- New: `download::ServerSlots` (`Default` caps within the process;
  `across_processes(dir)`, `with_notices(f)`, `max()`),
  `download::BudgetDrop`, `download::default_slot_dir()`,
  `DownloadOpts::for_item(&item)`, and the constants
  `download::MAX_CONNECTIONS_PER_SERVER` (6) and
  `download::MAX_CONNECTIONS_PER_FILE` (8).
- New: `download::zip::list_zip_contents_with`, `download_zip_member_with`
  and `download_zip_member_converted_with`, which hold a slot. The existing
  three keep their signatures and take no slot.
- New `IaError::RangeFailed`, not retryable; its JSON code is
  `range_failed`.
- Behaviour: every download request holds a slot on its datanode and goes
  over HTTP/1.1.
- New dependency `fs4` 1.1.0. The tokio floor is now 1.37.
- `ia-cli` gains `ia_cli::command()`.
